# Практика: «Сервис зелёный, а пользователи жалуются»

Вы — DevOps-инженер учебной команды. Frontend-разработчик доступен для обсуждения. Работайте только локально: никаких изменений production и деплоя.

## Входящее сообщение

> На телефоне атлас неудобно смотреть: карточки уходят вправо и появляется горизонтальная прокрутка. На ноутбуке вроде всё нормально. Проверьте, сервер ли это, и передайте команде понятное описание.

## Задача

1. Запустите репозиторий по README и воспроизведите жалобу в DevTools на ширине 390 px. Сравните с 1440 px. Зафиксируйте браузер, размеры viewport и скриншот.
2. Проверьте `/health`, `/api/planets`, HTTP-статусы CSS/JS и Console/Network. Опишите, какие факты подтверждены и чего health-check не показывает.
3. Запустите API и UI-тесты. Объясните, почему зелёный API не гарантирует корректную верстку. Укажите известные XFAIL.
4. Передайте frontend-команде сообщение по [шаблону](incident-template.md): симптом, влияние, воспроизведение, ожидаемое и фактическое поведение, доказательства, гипотеза и следующий шаг.
5. После согласования в учебной команде найдите и исправьте причину. Проверьте 375, 390, 640, 768 и 1440 px, поиск, фильтр и пустую выдачу. Уберите метку ожидаемого падения и повторите все тесты.

Не предлагайте перезапуск сервера как исправление без доказательств. Не обвиняйте команду и не выдавайте гипотезу за установленную причину. Если пробуете `overflow-x: hidden`, объясните, исправляет ли это размеры карточек или только скрывает симптом.

## Результат

Сообщение коллеге с доказательствами, локальный CSS-патч, результаты проверок до/после и короткое объяснение границы ответственности backend/frontend/DevOps. Примерный приоритет: P2 для учебного сценария — контент читается частично, обходной путь есть. Обоснуйте собственную оценку влиянием, а не цветом мониторинга.

Сначала проведите самостоятельную диагностику. [Памятка наставнику](mentor.md) раскрывает решение.
